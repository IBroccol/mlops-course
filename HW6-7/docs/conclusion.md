До генерации сохранён [protocol.md](protocol.md). Golden: 60 разных сущностей
из test ДЗ3, по 20 на каждую задачу; метки A/B/C по 20. Пять срезов всего,
три задачи — критические. City/country пересекаются с задачами.
Данные и журнал разметки в DVC; приложение подготовлено локально в `submission/`; публикация ожидает разрешения.
Источник — сохранённые карточки Wikidata от 2026-09-17 (CC0), без сетевого
обновления. Вручную на уровне этого выполнения проверены факты карточек,
столицы и знаки координат; проверку выполнял Codex, независимый эксперт
человек её не выполнял. Неоднозначность текущих геополитических названий
снята формулировкой «согласно карточке», а не утверждением о текущем мире.
Полные 2 872 train-вопроса / 718 групп, 60 golden-групп, 0 пересечений
нормализованного текста/групп; behavioral тоже вне train. Повторный encoder
ДЗ4 дал точное совпадение всех 2 872 примеров. Смысловая контаминация этой
проверкой не исключается полностью. Эти 60 групп теперь regression set,
поэтому оценка не называется независимым final audit.

Обе модели получили одни input/system, greedy, seed42, thinking=false, 32 токена.
Эталонное поле expected в prompt не включалось. Невалидные ответы и аварии
остаются в знаменателе. Scorer требует строгий JSON с одним полем answer.

## Behavioral и решение о выпуске

Формат и перефраз вопроса о Мира-Бхаяндаре возвращают правильный JSON A.
Запрос функции Python вне географии получает JSON REFUSE. У базы и
кандидата 3/3 correct, 3/3 valid; behavioral не включён в golden n=60.
Связанные format/paraphrase имеют одну group_id, это не независимые примеры.
Гейт **FAIL**: общая accuracy упала и критический hemisphere упал с 10/20
до 6/20. `make promote` штатно пропущен. Champion отсутствует, candidate
сохранён. Baseline не обновлялся. Следующий эксперимент: добавить в train
задачи о знаках координат и совместимый JSON-контракт на новых сущностях;
после разработки потребуется отдельный untouched audit, а не настройка
по этим 60 вопросам. В рамках этой работы бюджет/порог не менялись.

Отрицательные проверки: выданный `make check-negative` портит копию ответов
и получает отказ (в том числе из-за несогласованных behavioral counts).
Дополнительный `scripts.negative_raw` портит **только raw golden**, пересчитывает
все counts и оставляет behavioral прежним: accuracy=0, format_rate=0,
гейт отклоняет по реальным регрессиям. Веса и alias обе проверки не меняют.

`make check-storage` выполнил реальный `--force-recreate` и вернул probe с тем
же SHA256. `make check-all`: 9/9 MLflow-проверок и 24/24 unit/integration.
Отпечаток выданных tests/ **c42ac7788026**, файлы не изменены.

## Ограничения оценки

Низкий teacher-forced loss измеряет продолжение эталонного текста по
данным ДЗ4. Он не проверяет строгость JSON и правильность авторегрессионного
выбора метки, поэтому его снижение совместимо с наблюдаемой регрессией.
BLEU/ROUGE могут вознаградить общие слова при неправильном городе или
знаке координаты; BERTScore допускает смысловую близость противоположных
фактов. Для MCQ меток точная проверка прозрачнее. LLM-судья мог бы помочь
разбирать открытые справки ДЗ5 по рубрике фактичности/полноты, со слепым
A/B, перестановкой порядка и сохранением вердикта. Его риски: предпочтение
длины и стиля, позиционное смещение, нестабильность и уверенная фактическая
ошибка. В обязательной части судья/платный API не использовались.
60 вопросов и 20 на критический срез дают грубые частоты; доверительная
устойчивость улучшения не доказана. На hemisphere большая доля северо-
восточных объектов; для следующего audit нужна стратификация по четырём
полушариям. Проверяется чтение карточки, а не географический поиск/RAG.
