# Четыре дефекта ДЗ6: причины, исправления, доказательства

## 1. Шесть моделей записывались в один run

В `src/sweep.py` дочерний `all-candidates` создавался снаружи цикла. Параметры
логировались только для первого кандидата; следующие метрики и модель
перезаписывали его результат. `start_run(name, nested=True)` перенесён внутрь
цикла. Теперь у родителя `415038bbdc514d81a0a40526511139ab` **6 различных FINISHED children**,
каждый со своими r, lr, target_modules, четырьмя train-точками и val на шагах
0, 2, 4. Проверки 1 и 3 проверяют сервер, а не число строк в локальном CSV.

## 2. Файлы исчезали после замены контейнера

Postgres имел volume, artifact store — нет. Метаданные переживали замену,
адаптеры оставались в writable layer старого контейнера. В `compose.yaml`
к сервису MLflow подключён именованный `artifacts:/mlartifacts`; сервер
использует `--serve-artifacts` и `--artifacts-destination=/mlartifacts`.
`make check-storage` создаёт случайный probe, сохраняет его SHA256, выполняет
`up --no-deps --force-recreate --wait mlflow`, скачивает probe и сравнивает
байты. Фактические run/SHA256/compose hash — `reports/storage-check.json`.
Postgres и существующие посторонние контейнеры не пересоздавались.

## 3. Train и val не имели версий в runs

`provenance()` вычисляла оба SHA256, но sweep удалял все ключи `data_*`.
Удалён этот фильтр. У всех шести runs одинаковые актуальные:

- train SHA256: `cd7978be151b5040fd2e3ff1e20bca8388917158746f5a3b168b493e8fe37092`;
- val SHA256: `82325ec177fec13a274d218feaece6afd1a6f4663dce5e76287ce6cc2c204fcd`;
- code SHA256: `61f9f8b259a2120ea2ba660f747af3bd9fb42029be136a938399b8ca80e04f93`;
- config SHA256: `aff8f4dec7d71c620711e60f2d064aa084f9b54f5be02b7b5bdd261ee638235a`.

База закреплена commit `c1899de289a04d12100db370d81485cdf75e47ca`.
В каждом run сохранены Python-исходники, config.json и uv.lock. На старте
sweep HEAD был `3db3d9171d699bae46053d4ef29036ef16653eb3` и `git_dirty=True`: исходники
фиксировались соседним коммитом `370d0b4`. Это не скрыто и не исправлялось
задним числом в тегах. Версия содержимого однозначна по сохранённому снимку
и code_sha256; проверка приёмки сравнивает его с текущим кодом.
Golden/behavioral/index дополнительно версионированы DVC. Полный индекс
из 2 872 строк сопоставлен с input_ids/labels/attention_mask из ДЗ4 точным
повторным выполнением encoder, а не сравнением одних id.

## 4. Порог по loss вычислялся, но не применялся

`promote()` делила final/base и сразу регистрировала модель, не вызывая
уже существующую `gate()`. Теперь gate выполняется до первой мутации
реестра: finite, положительная база, FINISHED и ratio ≤ threshold.
У выбранного кандидата ratio=0.541736 ≤ 1. Нулевой порог проверка 6
обязана отвергнуть до регистрации. Прямому `src.promote` запрещено
назначать champion: для него нужен `evaluation.cli promote` с полным
пересчётом качества по сохранённым raw. Конфиг части A использует candidate.

## Оценка и сохранность исходных проверок

Scorer и quality gate написаны в `evaluation/solution.py`. Дополнительно
JSON с повторным ключом или нечисловой константой отклоняется. Counts и
срезы пересчитываются из per_item, ошибки генерации не исключаются из n.
Проверяются совпадение протокола и наборов, конечность чисел, отсутствие
регрессии общей метрики/формата, критические срезы, все behavioral-кейсы.

Все выданные `tests/` сохранены побайтово. Отпечаток **c42ac7788026**.
Никакие критерии не ослаблены. `make check-all` включает девять проверок
реального MLflow/загрузки и 24 теста синтетического контракта оценки.
Синтетические fixtures не выдаются за ответы модели.

Источники: локальные лекции 1–7 и единое задание; официальная документация
[Docker volumes](https://docs.docker.com/engine/storage/volumes/).
