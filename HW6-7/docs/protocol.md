# Протокол до оценки кандидата, v1

Зафиксирован 21 октября 2026 до генерации ответов. Qwen3-0.6B с commit
`c1899de289a04d12100db370d81485cdf75e47ca`, greedy, seed 42, thinking off,
лимит 32 токена. Одинаковая system-инструкция из `evaluation/params.json`,
один chat template и scorer для базы и одного выбранного адаптера.

Golden: 60 разных сущностей из test ДЗ3, отсутствующих в полном train
(2 872 вопроса / 718 сущностей) и val. Три непересекающихся задания по 20:
извлечение страны города, определение полушарий по знакам координат,
извлечение столицы страны. Все три критические: справочник обязан сохранять
факты карточки и знаки координат. Дополнительные city/country пересекаются
с заданиями; их размеры нельзя суммировать с размерами заданий.
Ответы A/B/C сбалансированы по 20; варианты и порядок детерминированы до
запуска модели. Для каждой строки сохранены факт, варианты, ответ, URL
источника, SHA256 записи снимка, журнал проверки разметки.

Это проверка извлечения из карточки, не знания актуального мира. Источник —
локальный снимок Wikidata от 2026-09-17 (CC0). Истинность карточек на сегодня
не утверждается. Вопросы 60 выбранных test-групп теперь являются regression
set; оставшиеся группы не используются в подборе и оценке.

Scorer принимает только JSON-объект с единственным строковым ключом answer
и меткой из choices. Лишние поля, Markdown, повторные JSON-ключи, NaN,
пустой ответ и авария не дают правильного ответа. Все строки остаются в n.
Отдельно считаются format_rate, errors и показатели каждого среза.

Приёмка: общая accuracy и format_rate не хуже базы, accuracy каждого из
трёх критических срезов не хуже базы, все три behavioral (формат, перефраз,
отказ на программирование) верны. Генерационная ошибка, missing, NaN,
несовместимые хеши или несогласованные counts дают отказ. Допуск регрессии 0.
После результата пороги, prompt и метки не меняются. При отказе champion
не назначается, candidate и первоначальный baseline сохраняются.

Тесты fixtures проверяют код; реальные ответы считаются отдельно. До
регистрации действует loss-гейт final/base ≤ 1 на одном val из восьми
примеров. Подбор: шесть заранее указанных конфигураций, по четыре шага,
пул train 32, batch 1 × accumulation 2. Полный train-index, а не только
32/8 просмотренных примеров, используется для проверки утечки.
