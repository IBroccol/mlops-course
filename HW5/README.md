# ДЗ 5 — LoRA для географического датасета Wikidata

Обучение Qwen3-0.6B на собственных тензорах из ДЗ4: 2 872 train-примера и
360 validation-примеров из версии v2 ДЗ3. Модель извлекает факты из карточки
Wikidata и сохраняет ограничения снимка от 17 сентября 2026 года.

Два варианта используют одинаковые данные и гиперпараметры:

- `all_layers`: LoRA r=8 на семи проекциях каждого из 28 слоёв;
- `freeze14`: LoRA только на слоях 14–27, нижние слои и вся база заморожены.

Конфигурация находится в `params.yaml`: bf16, выбор устройства `auto`,
learning rate `2e-4`, seed 42, одна полная эпоха, batch 4 × accumulation 8.
Для оценки используется batch 8; конфигурация рассчитана на 36 ГБ RAM.
Эффективный батч 32 даёт 90 шагов на весь собственный датасет; последние
24 примера также участвуют в обновлении. Gradient checkpointing включён.
Используются обычные `train.pt` / `val.pt`: packing требует отдельной маски
между примерами, которой этот цикл обучения не реализует.

## Запуск

Из `HW5/`:

```bash
uv sync --locked
make train        # оба варианта и docs/curves.png
make compare      # база и all_layers на пяти фиксированных вопросах
make check        # девять проверок, в том числе офлайн-загрузка и повторяемость
```

Входные пути указывают непосредственно на `../HW4/data/tokenized/`; данные
не копируются и не подменяются курсовым срезом. На новом checkout сначала
нужен выход ДЗ3 и токенизация ДЗ4:

```bash
cd ../HW3
uv sync --locked
uv run dvc pull
make repro
cd ../HW4
uv sync --locked
mkdir -p data
cp ../HW3/data/train.jsonl data/train.jsonl
cp ../HW3/data/val.jsonl data/val.jsonl
make tokenize
cd ../HW5
```

Для автономной загрузки папки адаптера нужны установленные зависимости и
заранее закешированные веса базовой модели. Токенизатор и `chat_template`
сохраняются вместе с адаптером; сеть для их загрузки не нужна.

## Продолжение после перерыва

Каждые 10 шагов в `models/checkpoint_<variant>.pt` атомарно сохраняются
LoRA-веса, состояния AdamW и scheduler, генераторы случайных чисел, положение
в эпохе и кривые. Повторный `make train` автоматически продолжает совместимый
эксперимент; завершённый вариант восстанавливает уже полученный результат.
При изменении кода, lock-файла, конфига или данных начинается новый эксперимент.
Для полного повторения с нуля выполните `make clean` перед `make train`.

На Mac длительный запуск можно выполнить с `caffeinate -i make train`, чтобы
компьютер не уходил в автоматический сон. Закрытие крышки и выключение машины
всё равно прервут вычисления; следующий запуск продолжит сохранённый шаг.
Для машины с меньшим объёмом памяти уменьшите `train.batch_size` и
`train.eval_batch_size`, сохранив нужный эффективный батч через `grad_accum`.

## Результаты и сдача

- `docs/defects.md`: пять дефектов, фактические метрики и выводы эксперимента;
- `docs/curves.png`: train и val для обоих вариантов, включая val на шаге 0;
- `docs/compare.md`: пять вопросов из validation, карточки источника и ответы;
- `docs/compare_examples.json`: ID, группы и эталонные ответы этих вопросов;
- `docs/check.txt`: итог самопроверки с исходным отпечатком `06a02208c1f0`.

Все пять сущностей сравнения принадлежат validation; их карточки передаются
в контекст обеим моделям. Greedy-генерация ограничена 160 токенами, чтобы
помещались географические справки. Пять вопросов показывают изменение
поведения после подключения адаптера; общая оценка качества по ним не делается.

`tests/check.sh` сохранён побайтово. Для видео сдачи выполните `make check`
и покажите финальную строку вместе с отпечатком.

## DVC и артефакты

`dvc.yaml` описывает `train_all`, `train_freeze`, `compare` и `plot`, включая
зависимости от тензоров ДЗ4, кода, параметров и `uv.lock`. DVC инициализирован
в подпапке `HW5/`. Локальный remote — `../../dvc_remote_hw5`, рядом с общим
репозиторием; на другой машине нужно настроить доступное хранилище.

```bash
uv run dvc repro  # пересчитать изменившиеся стадии
uv run dvc push  # сохранить артефакты в настроенный remote
uv run dvc pull  # восстановить результаты по dvc.lock
```

Адаптеры, токенизированные данные, метрики JSON, логи и окружение исключены
из Git. В Git остаются код, конфигурация, lock-файлы, график и отчёты.
`make clean` удаляет результаты обучения; `make distclean` также удаляет `.venv`.
